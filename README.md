# DSH Pocket Monitor

在 iPhone 上**只读**查看 Windows 电脑上 DeepSeek Harness（DSH）的任务状态：当前会话、运行阶段、活动时间线、工具调用、相关进程，以及**真实的待审批请求**。

- 不改 DSH 源码，不开发 DSH 插件，不依赖任何第三方插件。
- 默认只在局域网可用；可选**公网模式**（用你自己的隧道），配对过的手机换网络也能看，未配对的一律看不到。
- 程序由你手动启动，退出即停止；不自动装任何东西、不改防火墙、不建隧道。
- 手机端**没有聊天输入框、没有命令输入、没有通用接口**，只能看状态 + 查看审批提示 + 处理本项目自己的令牌。

> 本项目读取的 DSH 数据源、接口实测结论与限制，都写在 **[docs/dsh-integration.md](docs/dsh-integration.md)** 里（全部是实测事实，不是推测）。

## 一分钟上手

```powershell
npm install          # 安装依赖（只装依赖，不改系统）
npm run build        # 构建手机端页面
npm run start:lan    # 启动局域网服务：打印访问地址 + 配对码 + 二维码
```

Windows 上也可以**直接双击 `start-lan.cmd`**：它会检查 Node 版本、按需安装依赖、按需构建前端，然后启动服务并打印二维码。脚本**不需要管理员权限**，也不会修改防火墙、不会改动 DSH、不会安装任何隧道客户端。

启动后终端会显示：

```
监听：0.0.0.0:3099
手机访问地址：http://192.168.x.x:3099/  (WLAN · wifi)
本次配对码：123456   有效期至 13:34:54；用过即失效
[二维码]

命令：r=刷新新配对码  d=设备列表  a=确认待配对  x=拒绝待配对  q=退出
```

## 环境要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| Windows | Windows 10/11 | 进程视图用的是 WMI + TCP 表，只在 Windows 上实现 |
| Node.js | **>= 22.6** | 后端用 Node 内置的 TypeScript 类型剥离运行，不需要额外加载器；`node:zlib` 的 Zstd API 也依赖这个版本 |
| 网络 | 手机与电脑在**同一个 Wi-Fi / 局域网** | 首期只支持 LAN，不支持公网 |
| DSH | 任意能写会话日志的版本（实测 0.2.0-rc.2） | 本项目只读 `$DSH_HOME/sessions` 下的日志 |

`npm install` 结束后会自动跑一次环境自检；也可以随时手动跑：

```powershell
npm run check:env
```

## 启动与退出

**启动（三种任选）**

```powershell
npm run start:lan        # 绑定所有网卡，手机可访问（推荐）
start-lan.cmd            # 双击启动的等价版本（Windows）
npm run start:host       # 只绑定 127.0.0.1，只有本机能打开（调试用）
```

常用参数（命令行参数优先于环境变量）：

```powershell
npm run start:lan -- --port 3100                 # 换端口
npm run start:lan -- --workspace D:\code\proj    # 监控另一个目录里跑的 DSH
npm run start:lan -- --dsh-home D:\dsh           # DSH_HOME 不在默认位置时
npm run start:lan -- --trusted-origin mypc.local # 允许额外的 Host 权威
```

**开发模式（改前端热更新）**

```powershell
npm run dev:backend      # 终端 1：后端（默认 3099）
npm run dev              # 终端 2：Vite 5173，自动把 /api 代理到后端
```

**退出**

- 交互式终端里按 `Ctrl+C`，或者在本终端输入 `q` 回车。
- 退出时会：关闭 HTTP 服务与所有手机实时连接 → 撤销尚未使用的配对码与待领取令牌 → 不留下后台常驻进程。
- **不会**终止 DSH，也**不会**动其他程序。
- 服务停止后，手机页面会显示「连接中断，正在重连…」；重新启动服务后刷新即可继续。

**端口被占用？** 程序会打印明确错误并给出换端口的命令（例如 `--port 3100`）。它**不会**去结束占用端口的程序，也**不会**修改 DSH 的端口。

## iPhone 访问流程（扫码配对）

1. 电脑上运行 `npm run start:lan`（或双击 `start-lan.cmd`），终端显示二维码和 6 位配对码。
2. iPhone 连上**同一个 Wi-Fi**，用**相机**扫描终端里的二维码 → 打开 Safari（二维码内容就是 `http://<电脑局域网IP>:<端口>/?pair=<配对码>`，不含任何 DSH 凭证）。
3. 页面会自动带上配对码提交配对请求；如果手动打开地址，就在页面上输入终端显示的 6 位配对码。
4. **在电脑上确认**（这是防止同网段其他设备抢先绑定的关键一步）：
   - 服务终端里按 `a` 回车 = 批准，按 `x` 回车 = 拒绝；或
   - 在任意终端执行 `npm run approve`，按提示输入 `y` / `n`。
5. 手机页面自动进入监控界面，设备令牌以 `HttpOnly` cookie 下发（只在这次轮询里发送一次，永不出现在 URL 或二维码里）。
6. 想长期使用：Safari 分享 → **添加到主屏幕**，之后从主屏图标打开，界面是竖屏全屏样式（PWA 清单已内置）。

**解绑**

- 手机端：设置 → 解除绑定。
- 电脑端：服务终端按 `d` 查看已绑定设备列表；也可以用管理接口撤销：

```powershell
# 列出设备（含 id、状态、过期时间）
curl http://127.0.0.1:3099/api/admin/session
# 撤销某台设备（id 取上一行的值）
curl -X DELETE http://127.0.0.1:3099/api/admin/devices/<设备id>
```

### 设备记录会自动过期清理

反复配对（比如排查网络时扫了好几次码）会留下多条 `iPhone` 记录。现在的规则：

| 情况 | 结果 |
| --- | --- |
| 超过 **30 天**没有任何请求 | 令牌失效，手机需重新扫码配对；记录仍留在列表里，标为「已过期」，方便你查看发生了什么 |
| 失效或已被撤销的记录再过 **30 天** | 自动从 `data/devices.json` 移除 |
| 命令 `POST /api/admin/devices/sweep` | 立刻手动清理一次（只允许本机访问） |

清理时机：服务启动时、每 6 小时、以及上面那个手动接口。想调整或关掉：

```powershell
npm run start:lan -- --device-ttl 90      # 90 天不用才作废
npm run start:lan -- --device-ttl 0       # 永不过期，只能手动撤销
```

查看当前状态（每台设备带 `status`：`active` / `expired` / `revoked`，以及 `expiresAt`）：

```powershell
curl.exe -s http://127.0.0.1:3099/api/admin/session
```

> 被 system 清理掉的那条记录，在手机上表现为「会话已失效，请重新配对」——重扫一次码即可，不影响其他设备。


## 界面说明

| 页签 | 内容 |
| --- | --- |
| **概览** | DSH 数据源状态、当前会话与状态（运行中/等待审批/空闲/失败/已取消/被中断）、当前轮次与步骤、本轮运行时长、最近活动时间、正在执行的工具调用 |
| **时间线** | 按时间倒序的活动事件：轮次、步骤、工具调用与结果、助手回复、用户输入、斜杠命令、审批、权限姿态。默认只渲染最近 40 条，点某一条展开详情，其余按需加载 |
| **进程** | 命令行可验证属于 DSH 的 `node.exe` 进程（PID、角色、监听端口、启动时间、脱敏后的命令行）。不枚举全部系统进程，绝不上传或终止任何进程 |
| **审批** | 真实待审批请求（工具名、请求 ID、工具调用 ID、原因、当时策略、所属会话）+ **一句话提示**（告诉你在电脑上要做什么）+ 最近审批结果 |
| **设置** | 本机设备信息与解绑、访问地址、公网模式状态、连接诊断、安全边界说明 |

界面细节：深浅色自适应、状态用**文字 + 图标**表达（不只靠颜色）、危险操作要**二次确认**、没有聊天框也没有终端输入框。

> **审批在手机上是「提示」而不是「按钮」**：因为 DSH 这一版没有面向外部进程的审批通道（理由见下文），手机端不会给你一个点了也没用的按钮，而是把 DSH 真正在要什么说清楚，例如：
>
> > DSH 需要你的授权：把沙箱提升到 danger-full-access，以便「执行命令行」（building the frontend needs to spawn a child process）。请在运行 DSH 的电脑上批准，手机端只能查看。
>
> 待审批项还带一个类型标签（沙箱提权 / 权限申请 / 联网访问 / 文件访问 / 需重试确认 / 工具授权 / 审批策略），和一个「提示汇总」复制按钮，方便你把待办一次性贴到别处。

## 配置项

全部可用**环境变量**或**命令行参数**设置（参数优先）。完整清单见 [.env.example](.env.example)。

| 命令行参数 | 环境变量 | 默认值 | 含义 |
| --- | --- | --- | --- |
| `--host` | `DSH_POCKET_MONITOR_HOST` | `0.0.0.0` | 绑定地址。绑 `0.0.0.0` 只是「监听所有网卡」，真正的访问控制靠 Host/Origin 校验 + 设备令牌 + 配对 |
| `--port` | `DSH_POCKET_MONITOR_PORT` | `3099` | 端口；传 `0` 由系统分配 |
| `--workspace` | `DSH_POCKET_MONITOR_WORKSPACE` | 当前目录 | 要监控哪个工作目录里跑的 DSH 会话 |
| `--dsh-home` | `DSH_HOME` | `%USERPROFILE%\.dsh` | DSH Home；会话日志在 `<dsh-home>\sessions` |
| `--poll` | `DSH_POCKET_MONITOR_POLL` | `1000` | 会话日志扫描间隔（毫秒，最小 200） |
| `--pair-ttl` | `DSH_POCKET_MONITOR_PAIR_TTL` | `300` | 配对码有效期（秒，最小 30） |
| `--data-dir` | `DSH_POCKET_MONITOR_DATA_DIR` | `.\data` | 存放已绑定设备、访问 PIN、本机审批尝试记录 |
| `--trusted-origin` | — | 无 | 额外允许的 Host 权威，可重复 |
| `--no-terminal-approval` | `DSH_POCKET_MONITOR_TERMINAL_APPROVAL=0` | 开启 | 关闭「本机扫码自动确认」，改为必须手动确认 |
| `--no-qr` | `DSH_POCKET_MONITOR_PRINT_QR=0` | 打印 | 不打印二维码 |
| `--device-ttl` | `DSH_POCKET_MONITOR_DEVICE_TTL_DAYS` | `30` | 已配对设备多少天没用就作废（需重新配对）；`0` = 永不过期，只能手动撤销 |
| `--public` | `DSH_POCKET_MONITOR_PUBLIC=1` | 关闭 | 启用公网模式（见下节） |
| `--public-url` | `DSH_POCKET_MONITOR_PUBLIC_URL` | 无 | 你在公网用的域名；不写则接受任何非本地 Host |
| `--behind-tls` | `DSH_POCKET_MONITOR_BEHIND_TLS=1` | 关闭 | 确认隧道/反向代理已终止 TLS（公网模式必需其一） |
| `--tls-cert` / `--tls-key` | `DSH_POCKET_MONITOR_TLS_CERT` / `_KEY` | 无 | 让本服务自己用 HTTPS（成对提供） |
| `--public-pin` | `DSH_POCKET_MONITOR_PUBLIC_PIN` | 自动生成 | 公网访问 PIN（4-12 位数字） |
| `--public-no-pin` | `DSH_POCKET_MONITOR_PUBLIC_PIN_REQUIRED=0` | 要求 PIN | 关闭 PIN 要求（**不推荐**：令牌泄露即失守） |

本项目的运行时文件只有两个，都在 `data/`（已在 `.gitignore` 里）：

- `data/devices.json`：已绑定设备（只存令牌的 SHA-256，不存原始令牌）
- `data/approval-attempts.jsonl`：本机记录的审批提交尝试（用于透明回溯，见下文）

## Windows 防火墙排查

服务绑定 `0.0.0.0` 后，**Windows 防火墙默认可能仍然拦住局域网访问**。请按顺序排查：

1. **先确认服务在跑**：电脑上打开 <http://127.0.0.1:3099/> 能看到界面。
2. **确认手机和电脑在同一网段**：电脑 `ipconfig` 看 WLAN 的 IPv4（例如 `192.168.1.23`）；手机 Wi-Fi 详情里看 IP，前三段应该一致。
3. **确认连的是正确的地址**：必须用电脑终端里打印的那个地址；`VMware`/`VirtualBox`/`WSL` 的虚拟网卡地址（例如 `192.168.56.1`、`172.16.0.1` 这类）手机连不上，不要用。虚拟网卡地址在终端里会标着 `virtual`，优先用标着 `wifi` 的那个。
4. **放行端口**（在**管理员** PowerShell 里执行一次即可，本项目不会自动改防火墙）：
   ```powershell
   New-NetFirewallRule -DisplayName "DSH Pocket Monitor (LAN)" -Direction Inbound -Action Allow `
     -Protocol TCP -LocalPort 3099 -Profile Private
   ```
   注意 `-Profile Private`：只对「专用网络」放行。如果 Windows 把当前 Wi-Fi 标成了「公用网络」，要么把它改成专用网络（设置 → 网络和 Internet → 属性 → 网络配置文件类型 → 专用），要么把 `-Profile` 改成 `Private,Domain`。**不建议**为了省事对 `Public` 放行。
5. **确认没有其他程序占用端口**：`netstat -ano | findstr :3099`。被占用就换端口（`--port 3100`）。
6. **还是打不开**：在手机上打开 `http://<电脑IP>:3099/api/health`，能返回 `{"ok":true...}` 说明网络通、是页面缓存问题；返回超时说明还是防火墙/网段问题。
7. 反向排查：电脑上执行 `Test-NetConnection -ComputerName <电脑IP> -Port 3099`，如果在电脑上自己都连不通，说明绑定地址写错了。

## 安全边界（请务必读一遍）

**本项目做的：**

- 手机只持有**本项目签发的受限令牌**（作用域固定为 `status:read`、`events:read`、`approval:view`），拿不到 DSH 的启动令牌、cookie 或任何 API 密钥。
- 后端**只读** DSH 的会话日志文件，**不代理** DSH 的 `/api`，不提供聊天、命令执行或任意 RPC 转发；即把按钮藏起来，后端也会拒绝越权请求。
- 每个请求都过 Host / Origin 栅栏：`Host` 必须是 loopback、本机地址或显式配置的权威；带 `Origin` 时必须与 Host 一致；`sec-fetch-site: cross-site` 一律拒绝（返回 403）。Host 可信但没认证 → 401。
- 配对码一次性、有有效期（默认 5 分钟）、有失败次数限制（同 IP 5 分钟 8 次），并且**必须在本机确认**才会下发设备令牌。
- **设备令牌与 IP 无关**：已配对的手机换网络（Wi-Fi ↔ 蜂窝）后仍然有效，不需要重新配对——这正是"公网也能看"的基础。
- 公网模式下再加一层：非回环请求必须同时给出**设备令牌 + 访问 PIN**，PIN 与令牌失败都有限速（PIN：每地址 10 次/10 分钟；令牌失败：每地址 30 次 + 全局 300 次/10 分钟）。
- 修改变更类操作只接受 `POST`/`DELETE`，且额外校验 Origin（CSRF 防护），审批接口用 `clientRequestId` 做幂等。
- 管理接口（`/api/admin/*`，含配对确认与设备撤销）**永远只允许本机回环访问**，公网模式下也一样。
- 退出时撤销临时配对码与待领取令牌，清理自己产生的状态文件。

**本项目不做的（请勿误解）：**

- **局域网 ≠ 安全**。局域网访问用的是明文 HTTP：同一 Wi-Fi 下的其他人理论上可以嗅探流量。请**只在可信的专用网络**里使用，不要在咖啡厅、酒店、公司访客网络等公共网络上启动。
- **公网模式不做明文暴露**：`--public` 必须同时给出 `--tls-cert/--tls-key`（本服务自己用 HTTPS）或 `--behind-tls`（你的隧道/反代已终止 TLS），否则**拒绝启动**。没有例外，因为明文暴露一个 bearer 令牌等于公开它。
- **不自动建隧道**：不下载、不安装、不启动任何隧道客户端，不改防火墙，不做端口转发，不用 UPnP。隧道由你自己准备。
- 不宣称「绑了 0.0.0.0 也只在局域网内」。是否真的只有局域网能到达，取决于你的网络拓扑与防火墙，本项目只负责 Host/Origin 校验、认证、限速与最小权限。

**日志与隐私**：启动日志只打印监听地址、访问地址、配对码有效期和关闭方法；**不打印任何设备令牌**（公网 PIN 例外：它只在生成的那一刻打印一次，因为你需要看到它；文件里只存哈希）。项目不会把 DSH 会话内容、个人目录路径或任何凭证写入日志或提交到 Git（见 [.gitignore](.gitignore)）。手机界面显示的进程命令行已做脱敏（`--token`/`api_key`/`sk-*` 一律替换成 `<redacted>`，`C:\Users\<你>` 替换成 `%USERPROFILE%`）。

## 换网络也能看：两种接法

第一版是纯局域网。现在把配对过的手机带到别的网络继续查看，有两条路：**Tailscale（推荐，只有你自己的设备能访问）** 和 **公网模式 + 你自己的隧道**（暴露面更大，适合要给外人看）。

| | **A. Tailscale（推荐）** | **B. 公网模式 + 你自己的隧道** |
| --- | --- | --- |
| 谁能访问 | 只有登录你账号的设备（tailnet 内） | 视隧道而定，可能是真公网 |
| 加密 | Tailscale 端到端（WireGuard） | 由隧道/反代终止 TLS |
| 需要访问 PIN | ❌ 不需要 | ✅ 需要（默认） |
| 需要端口转发/改防火墙 | ❌ 不需要 | ❌ 不需要（隧道是出站连接） |
| 需要单独域名 | ❌ 不需要 | 用隧道的免费域名，或有自己的域名 |
| 能绕开「同一 Wi-Fi 设备不能互访」的网络限制 | ✅ **能** | ✅ 能 |
| 适用 | 主要图自己远程查看 | 要给不在你 tailnet 里的人看 |

### 为什么仍然要求配对

放行外部 `Host` 只解决"能不能连上"；"能不能看"永远由**设备令牌**决定：

- 未配对的设备（哪怕拿到了你的域名）→ 每一步都是 **401**，响应里连会话 ID 都没有。
- 已配对的设备 → 令牌与 IP 无关，所以换网络照样能用。
- 电脑端撤销设备 → 访问**立即**失效（实测覆盖）。

### 访问 PIN（第二道验证）怎么工作

设备令牌是 bearer 凭证：一旦泄露（浏览器同步、手机借人、代理日志）单独就够用了，所以**公网模式**默认再加一道 PIN：

1. 首次开启公网模式时，服务会生成一个 6 位 PIN 并在终端打印一次；文件里只存哈希。
2. 手机在新网络第一次访问时，页面会要求输入这个 PIN → 输对后本机记住，之后不用再输。
3. 忘记/想换：`npm run pin`（查看说明或重新生成），或 `npm run pin -- --public-pin 123456`。
4. 明确不想要（**风险自负**）：`--public-no-pin`，此时只靠设备令牌。

> Tailscale 这条路（接法 A）**不需要 PIN**，因为它本来就只对你的 tailnet 开放。

### 接法 A：Tailscale Serve（推荐）

**为什么推荐**：很多网络（校园网、单位网、酒店 Wi-Fi）会在接入点层面禁止**同一网段的两台设备互相访问**（客户端隔离）。这种限制跟你的防火墙、服务绑定地址都无关，你改不动。Tailscale 让手机和电脑各自连到它的通道上，**不经过你 Wi-Fi 的内部路由**，所以能绕开它，而且端到端加密。

**第 1 步：电脑上挂到 Tailscale 域名**

```powershell
# 先启动监控服务（普通终端窗口，保持开着）
npm run start:lan

# 另一个窗口：注册域名并代理到 3099（只需做过一次，之后长期有效）
tailscale serve --bg --https=443 http://127.0.0.1:3099
tailscale serve status
```

`tailscale serve status` 会打印类似 `https://<电脑名>.<你的tailnet>.ts.net` 的地址。注意这个域名与你电脑的 **MagicDNS 名字**有关（在 Tailscale 控制台改设备名后要重新确认）。

**第 2 步：让服务接受这个域名** ⚠️ **最容易漏的一步**

默认情况下服务只信任 loopback 和局域网地址，用域名访问会得到：

```json
{"error":{"code":"forbidden-origin","message":"Host xxx.ts.net 不在本服务的可信地址列表里。"}}
```

所以启动时要显式放行这个域名：

```powershell
npm run start:lan -- --trusted-origin <电脑名>.<你的tailnet>.ts.net
```

也可以设成环境变量少打字：

```powershell
$env:DSH_POCKET_MONITOR_TRUSTED_ORIGIN = '<电脑名>.<你的tailnet>.ts.net'
npm run start:lan
```

**第 3 步：手机配对（只需一次）**

1. 手机装 Tailscale 并登录**同一个账号**，开关打开
2. Safari 打开 `https://<电脑名>.<你的tailnet>.ts.net/`（⚠️ **结尾斜杠别丢**）
3. 输入电脑终端里的 6 位配对码 → 提交
4. **电脑上回到服务窗口，输入 `a` 回车**批准（从 Tailscale 来的请求不会被自动批准，这是防别人抢先绑定的设计）
5. 手机自动进入监控界面

**第 4 步：验证跨网络**

手机关掉 Wi-Fi、只留蜂窝数据（Tailscale 开关保持打开）→ 重新打开同一个地址 → 能看就完成了。建议「分享 → 添加到主屏幕」，以后一个图标进。

**更省事的地址**：服务绑定 `0.0.0.0`，所以 Tailscale 的 `100.x.x.x` 地址也是通的（实测 `http://100.x.x.x:3099/api/health` 返回 200）。把常用地址记成 `http://<Tailscale IP>:3099/` 就能完全绕开域名和证书。想更短就改设备名（见下一节）。

### 接法 B：公网模式 + 你自己的隧道

**只在需要把访问权给 tailnet 之外的人时，才比接法 A 更合适**（代价是暴露面更大，所以强制 TLS + PIN）。

```powershell
# 1. 电脑上启动服务，声明你要用的公网域名 + 让隧道终止 TLS
npm run start:lan -- --public --public-url mon.example.com --behind-tls

# 2. 记下终端打印的访问 PIN（只显示这一次）

# 3. 用你自己的隧道把它接出去（示例；本项目不会替你装）
#    cloudflared tunnel --url http://127.0.0.1:3099
#    然后把隧道给你的域名填进 --public-url（或换成你自己的域名 + 反向代理）

# 4. 手机在任意网络打开那个 https:// 域名 → 输入 PIN → 看到真实的 DSH 进度
```

换成 ngrok、Tailscale Funnel、Caddy/Nginx 反代同理：**TLS 由它终止，本服务只管认证与限速**。

### 把地址变短：域名与 IP

- **改电脑名（最省事，免费、立刻生效）**：Tailscale 的域名后半段是固定的，只能改前半段。去 https://login.tailscale.com/admin/machines → 找到你的电脑 → `⋯` → **Edit machine name** 改成例如 `dsh`，域名就变成 `https://dsh.<你的tailnet>.ts.net/`。如果改完域名没变，说明它跟着 Windows 计算机名走（那就用下面第二条）。
- **直接用 Tailscale IP**：`http://<100.x.x.x>:3099/`，不用域名也不用 HTTPS（走 Tailscale 隧道本身就是加密的），适合记成书签。
- **真·自定义域名**（例如 `mon.mydomain.com`）：**Tailscale 做不到**——它只发 `*.ts.net` 证书。想要自己的域名只有两条路：
  1. **有域名 + 反向代理**（Caddy/Nginx）指向 `127.0.0.1:3099`，用 DNS-01 签 Let's Encrypt 证书，然后把域名加进 `--trusted-origin`。和接法 B 的体力活一样，但访问范围仍限制在 tailnet 内（需要把 DNS 解析到 Tailscale IP，或只在自己设备上用自定义 DNS）。
  2. **用 Tailscale Funnel** 把服务推到公网，再套自己的域名（这时就该用 `--public` + PIN 了）。

> 结论：**只为自己远程看**，改个短设备名 + 记 `http://<Tailscale IP>:3099/` 就够了，不值得为自定义域名引入证书和反向代理。

### 想收回去

```powershell
npm run start:lan                          # 不带 --trusted-origin/--public：外部域名立刻 403
tailscale serve reset                      # 注销域名（手机上的 .ts.net 地址随即失效）
npm run pin -- --public-pin 000000         # 换掉 PIN（若你开了公网模式）
```

手机端「设置 → 访问范围」里能随时清除本机记住的 PIN；「解除绑定」则会让这台设备在所有网络上立刻失效。

### 受 DSH 现有接口限制（**没有**实现，并且**不会**假装成功）

| 功能 | 状态 | 原因（实测） |
| --- | --- | --- |
| **由手机把审批决定下发到 DSH** | ❌ 当前 DSH 版本无法实现 → 改为**一句话提示** | DSH 0.2.0-rc.2 的审批决定只在 DSH 进程内的 `approval/request` waterfall 里产生（`@deepseek-ai/dsh-user-approval`）；Web GUI 之所以能点审批，是因为它是**进程内**的应答者（`dsh-api-remotes` 转发 + `dsh-client-ui-approval` 作答），而那条通道要求操作者级浏览器会话。会话日志是仅追加产物，**写它不会影响正在运行的 DSH**。因此手机端**不显示**批准/拒绝按钮，而是给出提示（见上）；后端仍保留完整的权限/请求 ID/状态/幂等校验，接口返回 `approval_channel_unavailable`（HTTP 501）+ 电脑端操作指引，**不会**模拟批准成功，也**不会**用通用 RPC 代偿 |
| 整体任务完成度百分比 | ❌ 不做 | DSH 不提供整体完成度，本项目改显示「当前阶段 + 最近活动 + 运行时长」，不编造百分比 |
| 聊天 / 新建任务 / 执行命令 | ❌ 明确不做（也是设计目标） | 手机端与后端都没有这类接口 |
| **自动建立公网隧道** | ❌ 不做（设计如此） | 不下载、不安装、不启动任何隧道客户端。公网模式只负责"接受你的域名 + 认证 + 限速"，隧道由你自己准备 |

**审批为什么不能从外部进程下发（更细的说明）**

- `approval/asked{id,toolName,callId?,reason?}` 与 `approval/decided{id,outcome}` 会**成对写入会话日志**，所以我们能真实地「看到」待审批。
- 但决定本身来自进程内的应答者；外部进程既拿不到 DSH 的启动令牌（那需要你自己读终端，本项目也不会去读 `.credentials.yaml` 伪造 cookie），也没有任何官方的审批回写通道。
- 结论：本项目把**权限校验、请求 ID 校验、状态校验、幂等性**这些能做对的部分全部真实实现并测试（这是本项目自己的接口，也是未来接入真正通道后唯一需要替换的一层），**只有「下发」这一步如实返回不可用**；界面直接把 DSH 在要什么说清楚。
- 每一次提交尝试都会记到 `data/approval-attempts.jsonl`，方便你核对「手机点了什么、有没有被真的下发」。

```
    dist/                           # 构建产物（由 npm run build 生成，git 忽略）
  shared/types/                     # 前后端共用的数据模型
  scripts/                          # 环境自检、开发启动、测试运行器、端到端自检
  docs/dsh-integration.md           # 勘查结论：真实接口、事件结构、限制（实测）
  start-lan.cmd                     # Windows 一键启动
```

## 常见问题（FAQ）

**Q：手机上显示「配对码不正确或已失效」？**
在电脑终端按 `r` 生成新码再试。配对码默认 5 分钟有效、只能成功用一次；也可以加大有效期：`npm run start:lan -- --pair-ttl 900`。

**Q：手机上「连接中断，正在重连…」一直不恢复？**
先确认电脑上的服务还在跑、手机还在同一 Wi-Fi；页面会自动重试（500ms→1s→2s→4s→8s→10s，之后持续重试）。如果显示「会话已失效，请重新配对」，说明设备被解绑或撤销了，重新扫码即可。

**Q：看不到会话 / 状态一直「等待 DSH 会话日志」？**
本项目只监控「正在写会话日志的那个工作目录」。请在**要监控的目录**里启动 DSH，或者启动监控时显式指定：`npm run start:lan -- --workspace D:\code\proj`。DSH 还没在那个目录跑过时，界面会如实显示「还没找到会话日志」，不会编造数据。

**Q：为什么事件有几秒延迟？**
DSH 是**按批次**把事件落盘（每批一个 Zstandard 帧 + `fsync`），不是逐 token 流。本项目按文件长度变化增量解码，所以延迟通常是毫秒到秒级，不承诺「逐字实时」。

**Q：进程页是空的 / 提示进程视图不可用？**
先确认 DSH 真的在跑（`netstat -ano | findstr :3080`）。如果提示 WMI 看不到任何 `node.exe`，说明当前运行环境（某些受限上下文）挡住了 WMI 查询——本项目会如实报告为不可用，而不是给你一个空的假列表。

**Q：能顺便在手机上回消息、跑命令吗？**
不能，这是设计目标：本项目**只做监控与既有审批的查看**，没有聊天与命令通道。

**Q：手机和电脑同一个 Wi-Fi 了，还是「网络出错，无法显示该页面」？**
很可能是这个 Wi-Fi 开了**客户端隔离**（接入点禁止同一网段的两台设备互相访问）。这类限制与你的防火墙、服务绑定地址都无关，改不动。判断方法：手机浏览器打开 `http://<电脑局域网IP>:3099/api/health`，如果完全连不上（而不是返回 JSON 或 401），基本就是它。**解法：走 Tailscale**（接法 A），它不经过 Wi-Fi 的内部路由。

**Q：用 Tailscale 域名访问，返回 `forbidden-origin` / "Host ... 不在本服务的可信地址列表里"？**
这是正常的默认行为：服务默认只信任 loopback 和局域网地址。启动时显式放行你的 tailnet 域名即可：

```powershell
npm run start:lan -- --trusted-origin <电脑名>.<你的tailnet>.ts.net
```

不需要开 `--public`，也不需要 PIN。

**Q：能有个短一点的地址吗？**
三条路，从省事到费力：
1. **改 Tailscale 设备名**（最省事）：https://login.tailscale.com/admin/machines → `⋯` → Edit machine name → 改成 `dsh`，域名变成 `https://dsh.<tailnet>.ts.net/`。若改完域名没变，说明它跟的是 Windows 计算机名。
2. **直接用 Tailscale IP**：`http://100.x.x.x:3099/`（服务绑 `0.0.0.0`，这个地址实测可用，隧道本身已加密）。
3. **真·自定义域名**：Tailscale 只发 `*.ts.net` 证书，想要 `mon.mydomain.com` 就得自己上域名 + Caddy/Nginx 反代 + Let's Encrypt（DNS-01）。只为自用不太值得。

**Q：会不会自动帮我开隧道、从外面访问？**
不会自动开：本项目不下载、不安装、不启动任何隧道客户端，也不会改防火墙。远程访问用手动接法（Tailscale，或自己的隧道 + `--public`），见「换网络也能看」一章。

**Q：手机换到蜂窝网络后打不开了？**
两种情况：一是服务没开公网模式（那时只有局域网可达，这是默认）；二是开了公网模式但手机还没输入访问 PIN（页面会提示要 PIN）。已配对的设备本身不需要重新配对。

**Q：公网模式下别人拿到我的设备令牌会怎样？**
拿不到：令牌只在配对成功时通过一次轮询下发、之后存在 HttpOnly cookie 里，不进 URL、不进二维码。即使令牌泄露，公网请求还需要访问 PIN；而且你随时能在电脑端撤销设备（`npm run pin` 换 PIN 也行）。

**Q：程序退出后手机还能连吗？**
不能，退出即停止服务；临时配对码、待领取令牌与实时连接同时失效，需要重新启动并扫码。
